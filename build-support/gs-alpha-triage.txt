Facts below were decoded from saved sw/capture/corpus.bin GIF AD packets and
checked against sw/vk/gl binary capture snapshots. No production changes were
made for these findings. These are known remaining differences, not claims that
the current tool passes all cases or that a fix has been GPU-validated.

1. RGB_ONLY pass/fail partition reorders RGB writes on both hardware backends.

GSRendererHW::EmulateAlphaTest can select PASS_THEN_FAIL for RGB_ONLY.
Both passing and failing fragments write RGB, so processing all passing
primitives before all failing primitives changes the last RGB writer. The
simple dual-source RGB_ONLY path avoids this by writing colors in original
order; its availability must not be assumed on every GLES/Vulkan device.

Independent golden: matrix-0286 pixel (14,22).
TEST=0x3380d: alpha GREATER than128, AFAIL=RGB_ONLY, Z=ALWAYS.
PRIM=6: ABE is OFF, so this example does not depend on blending precision.
Sprite n2: RGBA=0x806ee93e, rectangle [14,33)x[15,40), Z=2.
Sprite n3: RGBA=0xff05f53d, rectangle [9,30)x[22,35), Z=3.
n2 fails alpha but writes RGB (62,233,110), preserving destination alpha.
n3 passes later and writes (61,245,5,255).
Software: (61,245,5,255). Vulkan/OpenGL: (62,233,110,255).
The hardware result is exactly the result of processing passing n3 before
failing n2. No rounding can explain replacing every channel by n2's bytes.

Independent blended golden: matrix-0285 pixel (14,24).
TEST=0x3380b: alpha GEQUAL128, AFAIL=RGB_ONLY, Z=ALWAYS.
ALPHA=0x4000000058: (Cs-0)*Ad/128 + Cd; PRIM=70, blending ON.
Background RGBA=0x80102030 (R48,G32,B16,A128).
n1 RGBA=0x7f747fdb, [12,17)x[20,35), fails alpha; B116.
n3 RGBA=0xff1af0ed, [14,37)x[24,50), passes alpha; B26.
Correct order: n1 writes B116+16=132 and keeps A128; n3 then writes
B26+132=158 and A255. Software=(255,255,158,255).
Pass-first order: n3 writes B42,A255; n1 then computes
floor(116*255/128)+42=273, clamped to255.
Vulkan/OpenGL=(255,255,255,255), exactly this reordered result.

Additional byte-exact examples:
matrix-1308 (29,28): Software R197, both hardware R132 (earlier failing n0).
matrix-1309 (3,26): Software R9, both hardware R103 (earlier failing n1).
matrix-1311 (28,22): Software=(177,29,255,255), both hardware all255.

Candidate future fix, NOT IMPLEMENTED:
Use existing ordered feedback for overlapping RGB_ONLY draws when supported,
with full primitive barriers on sampled feedback; preserve existing cheap
paths for independent/nonoverlapping draws. Exclude unproven DATE cases.
Required depth-feedback capability must be checked when Z writes are enabled.
Also inspect existing non-ROV feedback setup: it sets RGB_ONLY (3) even with
depth feedback and zwe, while shaders restore failing-fragment input_z only
for RGB_ONLY_SW_Z (5). The ROV setup already performs this promotion. Merely
forcing RGB_ONLY feedback without resolving this can introduce depth errors.

2. OpenGL ZB_ONLY feedback restores color before hardware blending.

opengl/tfx_fs.glsl final AFAIL handler replaces C with sample_from_rt() when
ZB_ONLY fails. A hardware blender still runs AFTER this replacement and can
transform that restored color again. Vulkan's two-pass route excludes the
failed fragment's color entirely, which explains the backend difference.

Independent golden: matrix-1815 pixel (10,27).
TEST=0x3280f: alpha NOTEQUAL128, AFAIL=ZB_ONLY, Z=ALWAYS.
ALPHA=0xff00000048: (Cs-0)*As/128 + Cd.
n2 RGBA=0x8035dc88, [10,39)x[27,49), A128, fails alpha.
No earlier sprite touches this pixel. ZB_ONLY must preserve the background
RGB=(48,32,16). Software/Vulkan do so.
The shader restores Cs=background, but As=128 still gives blend factor1;
hardware blending then computes background+background=(96,64,32).
OpenGL capture=(96,64,32,128), exactly this erroneous second blending.

Independent golden: matrix-1811 pixel (11,12).
TEST=0x32807: alpha LEQUAL128, AFAIL=ZB_ONLY.
ALPHA=0xff00000042: (0-Cs)*As/128 + Cd.
n3 RGBA=0xff4ea75f, [11,39)x[12,14), A255, fails alpha.
Correct output remains background=(48,32,16,128).
Applying this equation to the restored background with As255 makes RGB
negative, then clamps it to0. OpenGL=(0,0,0,128); Software/Vulkan preserve BG.
matrix-0533 (6,3) similarly preserves BG on Software/Vulkan but becomes black
on OpenGL; its first differing pixel is a separate one-byte rounding case,
so first_difference alone understates that scene's maximum error (48).

Candidate future fix, NOT IMPLEMENTED:
For AFAIL_ZB_ONLY color feedback, select the existing complete software blend
path and disable mixed/accumulation/fixed-function shortcuts. EmulateAlphaTest
runs before EmulateBlending, so the latter can inspect ps.afail/feedback flags.
Current force_sw_blending only treats framebuffer-fetch as already-needed
when barrier flags are also set; free framebuffer-fetch AFAIL can need the RT
without those flags. Reusing the existing force_sw_blending block would also
disable hybrid shortcuts. Ensure primitive-order barriers when sampling RT,
and validate alpha/discard/depth semantics with native regressions.

No shader, selector, blend configuration, build or device operation was changed
as part of this investigation. These candidate fixes require their own tests
and before/after GPU validation before being included in production.
